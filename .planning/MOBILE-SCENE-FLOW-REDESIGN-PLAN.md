# ImageThis 移动端场景生成流程减负计划

日期：2026-06-27  
PM 任务：T7 移动端场景生成流程减负与折叠交互计划  
目标页面：`/workspace/scene`

## 核心判断

当前移动端已经解决了“能用”和“不遮挡”的问题，但仍然偏桌面表单：用户先填写大量信息，再上传图片，再选风格，再进入生成设置。手机端更好的顺序应该是先拿到商品图，再让用户用少量必填项启动生成，其他信息折叠为可选增强。

目标不是把所有字段都塞进首屏，而是让用户在 390px 宽度下能快速完成这条主路径：

1. 上传商品图
2. 选择一个场景/风格
3. 补 1-2 个必要描述
4. 直接生成

## 推荐信息架构

### 移动端首屏：上传优先

首屏从现在的“产品基础信息”改为“素材与目标”：

- 商品图上传：主入口，放在最上方，占一行大按钮或紧凑上传卡。
- 参考图上传：次入口，和商品图并列成两个半宽卡，或折叠在“添加参考图”里。
- 产品名称：保留为轻量输入；如果上传文件名可读，可自动填入草稿。
- 产品类型：横向 pill，默认可不选。
- 主 CTA：底部仍固定，但文案改成“继续选风格”或当已有模板时“生成场景图”。

### 折叠分组

移动端默认展开：

- `素材上传`
- `基础描述`

移动端默认折叠：

- `更多产品信息`：目标人群、使用场景、核心卖点、使用平台。
- `高级生成设置`：模型、尺寸、候选数量、批量模式。
- `参考图`：若商品图已上传但参考图为空，可作为小入口，不占大块高度。

桌面端可以保持当前多段表单，不强制折叠。

### 步骤减少

移动端把三步弱化为两段：

- Step 1：准备素材和描述
- Step 2：选择风格并生成

现有 Step 3 的“生成设置”不再单独成步，迁入底部抽屉或折叠的高级设置。生成结果仍在同页展示。

技术上可以先不改 `type Step = 1 | 2 | 3` 的底层状态，而是移动端视觉上合并：

- 当前 Step 1 页面内增加上传优先和折叠表单。
- Step 2 卡片顶部直接露出“生成设置/高级设置”折叠块和“开始生成”。
- Step 3 保留为生成结果态，不作为用户必须配置的一步。

## 交互规则

- 所有枚举项手机端优先用横向 pill，不用 Select 弹层。
- 文本输入只保留必要短输入在默认展开区；长文本放进折叠区或单个“补充卖点”输入。
- 折叠区标题要带摘要，例如：
  - `更多产品信息 · 已填 2 项`
  - `高级设置 · Gemini / 1024 方图 / 4 张`
- 折叠区不使用嵌套卡片；每个分组是一个玻璃面板或无框分区。
- 底部 CTA 不被任何 FAB 覆盖；移动端全局 FAB 保持隐藏。
- 上传完成后卡片要变成清晰的已上传状态，显示文件名和替换入口。

## 实施批次

### Batch 1：首屏重排与折叠

- 将 `素材上传` 移到 `ProductInfoStep` 顶部。
- 将商品图和参考图压缩为手机友好的上传卡。
- 新增可复用 `MobileCollapsibleSection`，用于默认折叠内容。
- 将目标人群、使用场景、核心卖点、使用平台移入“更多产品信息”折叠区。
- 保持桌面布局基本不变，避免影响现有桌面工作流。

### Batch 2：生成设置后置

- 将移动端 `GenerateAdjustStep` 的模型、尺寸、候选数量收进“高级生成设置”折叠区。
- Step 2 风格选择页底部 CTA 改为可以直接进入生成；若缺商品图则提示上传。
- 生成设置摘要显示当前值，用户不打开也知道默认配置。

### Batch 3：减少步骤与验证

- 移动端 StepBar 文案调整为“素材 / 风格 / 结果”，弱化“填写大量信息”的心理负担。
- 验证 390x844 首屏可见上传区和至少一个核心选择入口。
- 回归 430x932、深色模式、登录态和无图/上传中/上传失败状态。

## 验收标准

- 390x844 下首屏必须看到商品图上传入口。
- 首屏不出现全局任务 FAB。
- 默认展开内容中，用户最多需要滚动一次即可看到底部主 CTA。
- 枚举选择项在手机端没有 Select 触发器；使用横向 pill。
- 折叠区触控目标不低于 44px，展开/收起状态有清晰摘要。
- `npx tsc --noEmit`、`npm run lint -- --quiet`、`npm run build` 通过。
- Playwright 移动端验证覆盖：
  - 初始态
  - 上传前 CTA
  - 已选择产品类型/平台
  - 展开更多信息
  - 展开高级设置

## 暂不做

- 不新增后端字段。
- 不改任务创建 API 合约。
- 不要求真实调用图像生成提供商。
- 不把桌面端改成同样折叠布局，除非后续桌面体验也明确需要。
