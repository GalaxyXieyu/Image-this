# Phase 5 Wave 1: Foundation (Schema + Registry + Result Types)

**Goal:** Add contract metadata to the database, create the handler registry interface, and define result contract types.

**Depends on:** Phase 4 complete

**Success Criteria:**
1. Prisma schema has `contractVersion`, `workflowType`, `handlerName` on `TaskQueue`
2. `prisma db push` succeeds without data loss
3. Handler registry interface exists with typed input validation
4. Result contract types exist for all workflow types
5. `npm run build` passes

## Tasks

Add to `prisma/schema.prisma` `TaskQueue` model:

```prisma

  workflowType     String?
```

Run `npx prisma db push` and `npx prisma generate`.

### Task 3: Create Handler Registry Interface

Create `src/lib/workbench/worker-handlers.ts`:

```ts
import type { WorkflowType, ToolParameters } from '@/types/workbench';
import type { WorkflowResult } from '@/types/workbench/results';

export interface QueueTask {
  id: string;
  type: string;
  inputData: string;
  totalSteps: number;
  userId: string;
  retryCount: number;
  maxRetries: number;
}

export interface WorkerContext {
  task: QueueTask;
  userId: string;
  updateProgress: (step: string, progress: number, completedSteps: number) => Promise<void>;
}

export interface WorkflowHandler<TInput extends ToolParameters, TResult extends WorkflowResult> {
  name: string;
  workflowType: WorkflowType;
  validateInput(raw: unknown): TInput;
  execute(ctx: WorkerContext, input: TInput): Promise<TResult>;
  normalizeResult(result: TResult): Record<string, unknown>;
}

export const WORKFLOW_HANDLERS = new Map<string, WorkflowHandler<any, any>>();

export function registerHandler<TInput extends ToolParameters, TResult extends WorkflowResult>(
  handler: WorkflowHandler<TInput, TResult>
): void {
  WORKFLOW_HANDLERS.set(handler.name, handler);
}

export function getHandler(name: string): WorkflowHandler<any, any> | undefined {
  return WORKFLOW_HANDLERS.get(name);
}
```

### Task 5: Update Worker to Use Registry (Fallback Mode)

Modify `src/app/api/tasks/worker/route.ts`:

- Import registry and handlers
- In `processNextTask()`, after claiming a task:
  - If `task.handlerName` exists and registry has it, use the handler
  - Otherwise fall back to the existing switch statement
- This is a safe increment — old tasks still use the switch, new tasks can use handlers

### Task 6: Update Task Creation to Set Contract Fields

Modify `src/app/api/tasks/route.ts` POST handler:

- When creating tasks, accept optional `contractVersion`, `workflowType`, `handlerName`
- Default `contractVersion` to 1 for legacy callers
- Frontend adapters will pass v2 fields in later waves
