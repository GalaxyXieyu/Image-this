# Plan 03-01: In-App Log Viewer And Configurable Log Directory

## Goal

让用户在应用内完成日志查看、错误定位、打开目录和目录配置，减少 Windows 安装版排障成本。

## Scope

- Electron 日志服务 IPC
- preload 类型声明
- 设置页日志诊断 UI
- 日志目录配置与兼容
- 基础敏感信息脱敏

## Implementation Plan

1. 抽出桌面日志路径解析
   - 当前 `LOG_DIR` 在 `electron/main.js` 顶部固定为 `~/ImagineThis/logs`。
   - 新增 `resolveLogDir()`，优先读取桌面配置中的自定义目录，否则使用默认目录。
   - 默认目录建议短期继续兼容 `~/ImagineThis/logs`，避免用户升级后找不到旧日志；界面展示实际路径。

2. 增加 Electron IPC 日志 API
   - `logs:get-info`: 返回当前目录、当前 app/error 文件、是否自定义。
   - `logs:list-files`: 只列当前日志目录下 `.log` 文件，返回名称、大小、修改时间。
   - `logs:read-tail`: 读取指定日志文件末尾 N 行或 N KB，限制最大读取量。
   - `logs:open-directory`: 用系统文件管理器打开日志目录。
   - `logs:choose-directory`: 选择自定义日志目录并保存。
   - `logs:reset-directory`: 恢复默认目录，不删除旧日志。

3. 重建日志写入流
   - 切换目录后关闭旧 `logStream/errorLogStream`。
   - 在新目录创建今日 `app-YYYY-MM-DD.log` 和 `error-YYYY-MM-DD.log`。
   - 写一条迁移记录，说明目录已切换。

4. preload 暴露受控 API
   - 在 `electron/preload.js` 暴露 `window.electron.logs`。
   - 更新 `src/types/electron.d.ts`，给前端补类型。

5. 设置页新增“日志诊断”
   - 左侧新增分区，放在“后台任务”和“应用更新”附近。
   - 顶部显示当前日志目录、打开目录、选择目录、恢复默认。
   - 中间显示日志文件列表。
   - 右侧或下方显示 tail 内容，默认打开 error 日志，没有 error 则 app 日志。
   - 支持刷新、复制当前日志片段。

6. 敏感信息处理
   - 主进程返回日志内容前做轻量脱敏。
   - 覆盖常见字段：`apiKey`, `secretKey`, `token`, `Authorization`, `AccessKey`, `SecretKey`。
   - 不做复杂解析，避免破坏日志可读性。

7. 验证
   - Mac 开发环境验证 IPC、日志列表、tail、打开目录。
   - Windows 实机验证安装版默认目录展示、打开目录、切换目录后继续写日志。
   - 验证切换日志目录不会改动数据库路径和历史任务。

## Acceptance Criteria

- 用户可以在设置页看到当前日志目录。
- 用户可以在应用内查看最近 app 日志和 error 日志。
- 日志读取不会一次性加载整个大文件。
- 用户可以点击打开日志目录。
- 用户可以选择自定义日志目录，并且新日志写入新目录。
- 恢复默认目录不会删除自定义目录里的旧日志。
- Windows 更新/重装后数据库不受影响。

## Risks

- 自定义日志目录无写权限时，需要回退默认目录并在界面提示。
- 旧日志目录迁移若自动移动文件，可能带来数据丢失风险；第一版不自动移动，只展示路径。
- 日志里可能已有敏感信息，应用内展示必须至少做基础脱敏。
