# AI Studio 2.0 PRD：电商视觉生产工作台

> 版本：v0.1 Draft  
> 创建日期：2026-04-28  
> 分支：`feature/ai-studio-2-commerce-workbench`  
> 关联旧文档：`docs/ai-studio-design.md`

## 1. 背景

当前产品已经具备一键增强、背景替换、扩图、高清化、水印、图生视频等能力，但这些能力以“工具 Tab”的方式并列呈现。对电商用户来说，真实目标不是“我要调用某个工具”，而是“我要为商品生产可上架、可投放、可复用的一批视觉素材”。

因此，AI Studio 2.0 的重构目标是：把产品从“AI 图片处理工具箱”升级为“电商视觉生产工作台”。用户在主界面选择常用生产场景，进入后创建批量任务；任务管理负责展示批次、商品、图片、工序的层级状态；模板资产中心负责沉淀可复用的场景、参考图、品牌和后处理配置。

## 2. 产品定位

### 2.1 一句话定位

面向电商卖家、运营和设计师的商品视觉批量生产工作台。

### 2.2 目标用户

| 用户 | 核心诉求 | 典型场景 |
|---|---|---|
| 电商卖家 | 快速生成商品上架图 | 新品上架、批量铺货 |
| 店铺运营 | 批量生产活动图和场景图 | 节日活动、社媒投放 |
| 电商设计师 | 用模板和参考图提高出图稳定性 | 套图统一风格、品牌视觉一致 |
| 内容投放人员 | 将商品图延展为海报和视频素材 | 广告素材、小红书/短视频封面 |

### 2.3 产品原则

1. 主界面展示用户常用功能，不展示“生产计划”这种内部概念。
2. 所有核心功能默认支持批量。
3. 生成能力和后处理能力分层：先生成结果图，再可选扩图、高清化、水印、局部编辑、图生视频。
4. 任务管理按业务层级展示，不按底层 TaskQueue 平铺。
5. 模板不局限于 Prompt，要支持图片参考、品牌资产、后处理流水线和历史结果沉淀。

## 3. 信息架构

主界面保留常用功能入口，用户先回答“我要做哪类图”，而不是先面对底层工具。

| 一级入口 | 用户理解 | 说明 |
|---|---|---|
| 电商套图生成 | 给商品生成 4/6/8 张上架图 | 核心入口，支持单商品和多商品批量 |
| 换背景 / 换场景 | 给商品换一个背景或使用场景 | 支持白底、场景参考图、风格背景 |
| 白底主图 | 批量生成平台白底图 | 高频快捷入口，本质是换背景模板 |
| 批量后处理 | 对已有图片扩图、高清化、加水印 | 处理已有图片或历史结果 |
| 图生视频 | 把图片生成商品视频 | 可基于上传图或生成结果图 |
| 模板资产中心 | 管理场景、参考图、品牌和后处理模板 | 复用和沉淀资产 |
| 任务管理 | 查看所有批次任务和历史结果 | 展示进度、失败、下载、重试 |

## 4. 能力模型

### 4.1 基础生成能力

基础生成能力负责从商品输入得到一批基础结果图。

| 能力 | 作用 | 输出 |
|---|---|---|
| 换背景 / 换场景 | 为商品生成 1 张或少量场景图 | 单张或少量结果图 |
| 套图生成 | 为每个商品生成 4/6/8 张不同用途的电商图 | 多张结果图 |

说明：套图生成是用户视角的基础生成入口，系统内部可以拆成多个场景生成任务。

### 4.2 后处理能力

后处理能力作用于已经生成或上传的图片。

| 能力 | 作用对象 | 推荐位置 |
|---|---|---|
| 扩图 | 原图、换背景结果、套图结果 | 自动流水线，可批量 |
| 高清化 | 原图、换背景结果、套图结果、扩图结果 | 自动流水线，可批量 |
| 水印 | 任意最终图片 | 自动流水线，通常最后一步 |
| 局部编辑 | 任意单张结果图 | 结果详情页手动触发 |
| 图生视频 | 任意图片结果 | 可作为自动步骤，也可手动触发 |

### 4.3 推荐生成链路

```text
商品输入
  ↓
基础生成能力
  - 换背景 / 换场景
  - 套图生成
  ↓
结果图池
  ↓
可选后处理流水线
  - 扩图
  - 高清化
  - 水印
  - 图生视频
  ↓
结果管理 / 下载 / 保存为模板
```

## 5. 核心功能流程

### 5.1 电商套图生成

目标：为一个或多个商品生成完整电商素材包。

流程：

1. 上传商品图，支持单图、多图、文件夹。
2. 选择套图模板：4 图、6 图、8 图，或用户自定义。
3. 选择参考模板：场景模板、参考图模板、品牌模板。
4. 配置后处理流水线：扩图、高清化、水印、图生视频。
5. 选择模型策略：推荐、质量优先、速度优先、成本优先、商品保持优先、创意场景优先。
6. 预览生成矩阵，确认总产出数量。
7. 提交任务，进入任务管理。

默认 8 图套装建议：

| 序号 | 场景类型 | 用户价值 |
|---|---|---|
| 1 | 白底主图 | 平台上架、搜索结果图 |
| 2 | 生活场景图 | 展示真实使用环境 |
| 3 | 卖点功能图 | 突出核心功能 |
| 4 | 细节特写图 | 展示材质、接口、质感 |
| 5 | 尺寸/对比图 | 帮用户理解大小、差异 |
| 6 | 使用步骤图 | 降低理解成本 |
| 7 | 搭配/组合感图 | 表达配套、拼单、关联销售 |
| 8 | 社媒海报图 | 小红书、广告、活动图 |

### 5.2 换背景 / 换场景

目标：为多个商品统一生成指定背景或使用场景。

流程：

1. 上传商品图。
2. 选择背景来源：白底、颜色背景、参考图、场景模板、Prompt。
3. 选择后处理流水线。
4. 预览任务：`N 个商品 × 1 张场景图`。
5. 提交任务。

### 5.3 白底主图

目标：批量生成平台上架所需白底图。

说明：这是“换背景 / 换场景”的高频快捷入口，应当在主界面独立展示，但底层复用同一套任务机制。

流程：

1. 上传商品图。
2. 选择平台规格：1:1、4:5、透明底、纯白底。
3. 选择后处理：扩图、高清化、水印。
4. 提交任务。

### 5.4 批量后处理

目标：对已有图片或历史结果继续加工。

支持输入：

- 本地上传图片
- 历史生成结果
- 某个任务批次中的全部或部分图片

支持流水线：

- 扩图
- 高清化
- 水印
- 图生视频

### 5.5 图生视频

目标：将商品图或结果图生成短视频。

流程：

1. 选择输入图片：上传图、历史结果、当前任务结果。
2. 选择视频模板：产品展示、生活场景、社媒广告、细节运镜。
3. 配置时长、比例、Prompt。
4. 提交任务。

## 6. 生成矩阵预览

生成前必须展示矩阵预览，帮助用户确认成本、数量和产出结构。

示例 1：套图生成

```text
20 个商品
× 8 张套图模板
× 高清化
× 品牌水印
= 160 张最终图
```

示例 2：白底图批量

```text
50 个商品
× 每个商品 1 张白底图
× 扩图到 1:1
× 高清化
= 50 张最终图
```

矩阵视图：

| 商品 | 白底主图 | 生活场景 | 卖点图 | 细节图 | 对比图 | 步骤图 | 搭配图 | 海报图 |
|---|---|---|---|---|---|---|---|---|
| 商品 A | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 |
| 商品 B | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 |

每个场景单元格支持查看或调整：

- 场景 Prompt
- 图片比例
- 推荐模型或模型策略
- 是否扩图
- 是否高清化
- 是否水印
- 当前状态

## 7. 任务管理

### 7.1 展示原则

任务管理不直接平铺底层原子任务，而是按业务层级展示。

```text
批次任务
  └── 商品
        └── 输出图片
              └── 工序步骤
                    └── 原子任务
```

用户默认看到批次任务；展开后看到商品和图片；再展开才看到具体工序。

### 7.2 一级任务列表

| 字段 | 示例 |
|---|---|
| 任务名称 | 春季新品 8 图套装 |
| 任务类型 | 电商套图生成 |
| 商品数量 | 20 个商品 |
| 结果数量 | 160 张图 |
| 当前进度 | 132/160 |
| 状态 | 生成中 / 已完成 / 部分失败 |
| 后处理 | 高清化 + 水印 |
| 操作 | 查看、重试失败、下载全部、复制为模板 |

### 7.3 任务详情

任务详情按商品分组。

```text
春季新品 8 图套装
  商品 A
    白底主图：完成
    生活场景：完成
    卖点图：生成中
    细节图：失败，可重试
  商品 B
    ...
```

单张输出图片详情展示工序：

```text
生活场景图
  1. 场景生成：完成
  2. 扩图：完成
  3. 高清化：处理中
  4. 水印：待处理
```

### 7.4 任务状态

| 状态 | 说明 |
|---|---|
| 草稿 | 用户配置中，尚未提交 |
| 排队中 | 已提交，等待 Worker |
| 生成中 | 基础生成阶段进行中 |
| 后处理中 | 扩图、高清化、水印、视频等步骤进行中 |
| 部分失败 | 批次内部分图片或工序失败 |
| 已完成 | 全部结果完成 |
| 已取消 | 用户取消 |

## 8. 模板资产中心

模板资产中心用于保存用户可复用的视觉资产和配置，不局限于 Prompt。

### 8.1 模板类型

| 模板类型 | 内容 | 用途 |
|---|---|---|
| 场景模板 | 场景名称、用途、Prompt、比例、推荐模型 | 套图生成、换场景 |
| 参考图模板 | 商品图、背景图、场景参考图 | 参考构图、背景、风格 |
| 后处理模板 | 扩图比例、高清化、水印、视频设置 | 批量生成后的自动处理 |
| 品牌模板 | Logo、水印位置、品牌色、固定文案 | 保持店铺视觉一致 |
| 结果模板 | 历史生成中效果好的结果图 | 下次作为风格或构图参考 |

### 8.2 模板中心结构

```text
模板资产中心
  - 场景模板
  - 图片参考
  - 后处理模板
  - 品牌资产
  - 我的收藏
```

### 8.3 保存为模板

每张生成结果图都提供“保存为模板”。

| 保存类型 | 说明 |
|---|---|
| 保存为参考图 | 下次作为风格、构图或背景参考 |
| 保存为场景模板 | 保存该图对应的 Prompt、比例和模型策略 |
| 保存为品牌模板 | 保存水印、Logo、版式配置 |
| 加入收藏 | 方便下次快速查找 |

## 9. 模型选择策略

普通用户不应直接面对复杂模型名称。默认展示模型策略，高级设置中再展开具体模型。

| 策略 | 用户理解 |
|---|---|
| 推荐 | 系统自动选择 |
| 质量优先 | 成本更高，结果更稳 |
| 速度优先 | 快速出预览 |
| 成本优先 | 适合大批量 |
| 商品保持优先 | 适合换背景和白底图 |
| 创意场景优先 | 适合套图、海报和生活场景 |

## 10. 数据对象建议

以下为产品层数据对象，具体实现可映射到 Prisma 和 TaskQueue。

| 对象 | 说明 |
|---|---|
| `GenerationBatch` | 用户可见的批次任务，例如“春季新品 8 图套装” |
| `BatchProduct` | 批次中的一个商品 |
| `OutputItem` | 某商品下的一张结果图或视频 |
| `ProcessingStep` | 输出项中的工序步骤，例如生成、扩图、高清化、水印 |
| `AtomicTask` | 底层 TaskQueue 任务 |
| `TemplateAsset` | 模板资产中心中的统一模板对象 |

建议关系：

```text
GenerationBatch 1 - N BatchProduct
BatchProduct 1 - N OutputItem
OutputItem 1 - N ProcessingStep
ProcessingStep 0 - 1 AtomicTask
TemplateAsset 可被 GenerationBatch / OutputItem 引用
```

## 11. MVP 范围

### 11.1 第一阶段必须做

1. 新主界面：展示电商套图生成、换背景/换场景、白底主图、批量后处理、图生视频、模板资产中心、任务管理。
2. 电商套图生成：支持单商品/多商品、默认 8 图套装、生成矩阵预览。
3. 换背景/换场景：支持批量，支持参考图和模板。
4. 后处理流水线：扩图、高清化、水印作为可配置步骤。
5. 新任务管理：按批次任务聚合展示。
6. 模板资产中心基础版：支持保存参考图模板、场景模板、品牌模板。

### 11.2 可后置

1. 局部编辑器深度集成。
2. 图生视频自动挂到每张套图结果之后。
3. 成本估算。
4. 模型自动路由和智能 Failover。
5. 多店铺品牌资产隔离。

### 11.3 暂不做

1. 独立“组合场景图”一级入口。
2. 将所有底层原子任务暴露给普通用户。
3. 以“生产计划”作为主界面核心入口。

## 12. 验收标准

1. 用户能从主界面选择“电商套图生成”，上传多个商品，并看到清晰的生成矩阵。
2. 用户能在提交前确认总产出数量，例如 `20 个商品 × 8 张图 = 160 张图`。
3. 用户能为生成结果配置扩图、高清化、水印后处理流水线。
4. 任务管理中，一个批次任务只展示为一条主记录，展开后可查看商品、图片和工序层级。
5. 用户能把一张生成效果好的图保存为参考图模板。
6. 用户能在下一次任务中复用已保存的参考图模板或场景模板。

## 13. 关键风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 批量任务过多 | 8 图套装会迅速产生大量图片和原子任务 | 批次聚合、并发限制、失败重试 |
| 任务状态复杂 | 生成、扩图、高清化、水印、视频状态可能不同步 | 引入 OutputItem 和 ProcessingStep 层级 |
| 模板资产边界变宽 | 模板不只是 Prompt，会涉及图片、品牌、后处理配置 | 统一 TemplateAsset 类型，按 category 区分 |
| 用户理解成本 | 功能强但可能配置复杂 | 默认模板 + 高级设置折叠 |
| 存储成本 | 历史结果和参考图模板会占用空间 | 后续加入容量、清理和归档策略 |

## 14. 后续开发建议

开发顺序建议：

1. 先实现产品信息架构和路由骨架。
2. 再实现批次任务数据模型，解决任务管理层级问题。
3. 然后接入电商套图生成的矩阵预览和提交流程。
4. 最后扩展模板资产中心和保存为模板能力。
