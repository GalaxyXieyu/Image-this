## 1. 背景

当前产品已经具备一键增强、背景替换、扩图、高清化、水印、图生视频等 AI 图片能力。旧形态更像“AI 图片工具箱”：能力以工具 Tab 并列呈现，用户需要理解底层工具，再自己组合成电商出图流程。

新版重构目标是把产品升级为“电商视觉生产工作台”：用户从商品视觉生产目标出发，上传商品资产，选择场景/模板/工具链，提交异步任务，在任务中心追踪进度，最后在结果库管理、下载和复用生成资产。

本 PRD 记录当前新版界面与交互基线，避免继续只靠实现推进。它不替代 `.planning/` 下的 GSD 执行文档；`.planning/` 负责阶段、计划和验收，本文件负责产品定义、页面关系、用户路径和业务规则。

## 2. 产品定位

### 2.1 一句话定位

面向电商卖家、运营和设计师的商品视觉批量生产工作台。

### 2.2 核心价值

电商卖家和运营可以用一个稳定、清晰、批量友好的 AI 工作台，快速产出商品主图、场景图、背景图、水印图、高清图和视频素材。

### 2.3 目标用户

| 用户 | 核心诉求 | 典型场景 |
|---|---|---|
| 电商卖家 | 快速生成可上架商品图 | 新品上架、批量铺货、白底主图 |
| 店铺运营 | 批量生产活动图和场景图 | 节日活动、社媒投放、店铺活动页 |
| 电商设计师 | 用模板和参考图提高出图稳定性 | 套图统一风格、品牌视觉一致 |
| 内容投放人员 | 将商品图延展为海报和视频素材 | 广告素材、小红书封面、短视频素材 |

### 2.4 产品原则

1. 用户先选择生产目标，而不是先理解底层模型或工具。
2. 核心流程默认支持批量，但单图使用不能变复杂。
3. 生成能力和后处理能力分层：先得到结果图，再可选扩图、高清化、水印、视频。
4. 任务中心按业务语义展示，不把底层原子任务直接暴露给普通用户。
5. 模板不只等于 Prompt，要能沉淀场景、参考图、品牌配置、工具参数和历史结果。
6. 桌面端体验是基线：本地 SQLite、本地文件路径、Electron 启动和 Windows IO 都必须被考虑。

## 3. 当前新版产品面

### 3.1 当前活跃路由

| 路由 | 页面角色 | 当前定位 |
|---|---|---|
| `/` | 产品首页和入口导航 | 解释产品价值，承接进入工作台、模板库和工具箱 |
| `/workspace/scene` | 主场景图生成工作流 | 当前 Phase 3 重点，承载商品信息、素材、生成和候选结果 |
| `/combo` | 多步骤工作流编排器 | 面向复杂组合任务，把多个处理步骤串成 pipeline |
| `/tools` | AI 图片工具箱 | 承载换背景、抠图、扩图、高清化等单工具能力 |
| `/tasks` | 任务中心 | 查看任务进度、状态、失败和完成入口 |
| `/results` | 结果管理 | 管理已生成资产，支持筛选、搜索、批量操作 |
| `/templates` | 模板库与预设中心 | 选择场景/工具/工作流预设，并进入对应工作流 |
| `/settings` | 设置中心 | 配置模型服务商、凭据、存储和运行参数 |

### 3.2 当前界面状态判断

当前产品已从旧工具箱方向进入新版工作台方向，但仍处于“新旧并存”的迁移阶段。

| 维度 | 当前状态 | PRD 口径 |
|---|---|---|
| 信息架构 | 新版 8 个主路由已明确 | 以商品视觉生产工作台为主线 |
| 导航 | 多数页面有相似顶部导航，但仍存在重复实现 | 后续应收敛成统一 Workbench Shell |
| 模板库 | `/templates` 最接近新版组件体系 | 作为新版工作台布局基准之一 |
| 场景工作流 | `/workspace/scene` 已接入真实任务创建和轻量轮询 | 作为核心生成流程继续补齐结果保存和验收 |
| 工具箱 | `/tools` 已有统一入口，但部分参数仍是 UI 层表达 | 后续需要接入真实处理契约 |
| 任务中心 | 能展示任务列表和状态 | 后续需要从原子任务视图升级为批次/商品/输出层级 |
| 结果管理 | 读取已完成图片结果 | 后续需要加强从任务完成到结果库的稳定闭环 |
| 任务系统 | 仍复用 legacy TaskQueue/worker | Phase 5 收敛 typed workflow contract |

## 4. 页面信息架构

### 4.1 首页 `/`

**页面角色**：产品落地页和主入口。

**主要区块**：

- 顶部导航：品牌、主页面入口、设置入口。
- Hero：说明“AI 商品视觉工作台”的价值。
- 快捷入口：进入场景生成、工具箱、模板库。
- 信任/能力展示：展示可完成的视觉生产能力。
- 案例区域：用于展示典型电商视觉产出。

**入口/出口**：

- 入口：应用启动默认页。
- 出口：`/workspace/scene`、`/templates`、`/tools`、`/tasks`、`/results`、`/settings`。

### 4.2 场景生成工作流 `/workspace/scene`

**页面角色**：当前核心生产工作流。用户在这里上传商品资产、选择生成意图、提交任务并查看候选状态。

**三阶段流程**：

| 阶段 | 用户目标 | 系统承接 |
|---|---|---|
| 1. 商品信息/素材收集 | 上传商品图，补充商品名称、品类、卖点、参考图 | 登记输入资产，形成 workflow draft |
| 2. 场景/参数配置 | 选择模板、场景、比例、风格、模型策略 | 形成可提交的任务请求 |
| 3. 生成与调整 | 提交任务、查看候选状态、选择结果 | 通过轻量轮询获取任务状态和候选结果 |

**当前交互主线**：

```text
首页或模板库
  ↓
进入 /workspace/scene
  ↓
填写商品信息和上传素材
  ↓
选择场景/预设/生成参数
  ↓
提交生成任务
  ↓
页面内展示候选卡片状态
  ↓
任务完成后进入结果查看或结果管理
```

**需要明确的当前边界**：

- `scene_generation` 是新版业务语义。
- 当前 worker 执行侧仍通过 legacy `BACKGROUND_REMOVAL` 分支承接。
- 真实 provider 完成、结果 URL 解析、保存到结果库的链路仍需 smoke 验证。

### 4.3 组合工作流 `/combo`

**页面角色**：多步骤流程编排器，适合把背景替换、扩图、高清化、水印、视频等能力组成 pipeline。

**主要区块**：

- 左侧：工作流模板/能力分类。
- 中间：步骤编排区，展示 pipeline 顺序。
- 右侧：当前步骤参数和执行设置。

**当前交互主线**：

```text
选择工作流模板
  ↓
调整步骤顺序和参数
  ↓
上传或选择输入图片
  ↓
提交一组任务
  ↓
跳转任务中心查看进度
```

**PRD 口径**：

`/combo` 面向高级用户和复杂任务，不应压过 `/workspace/scene` 的主生产入口。普通用户优先走模板和场景工作流，高级用户再进入组合编排。

### 4.4 工具箱 `/tools`

**页面角色**：单工具或轻量批处理入口。

**主要能力**：

| 工具 | 用户理解 | 目标位置 |
|---|---|---|
| AI 换背景 | 给商品换一个背景或场景 | 可被场景工作流和工具箱复用 |
| 抠图/去背景 | 得到透明底或干净主体 | 白底主图和换背景前置能力 |
| 扩图 | 适配比例或补充画面 | 后处理流水线能力 |
| 高清化 | 提升清晰度 | 后处理流水线能力 |
| 水印 | 添加品牌标识 | 后处理流水线能力 |
| 图生视频 | 从图片生成短视频素材 | 可在结果页或工作流中触发 |

**当前边界**：

部分工具参数已在界面表达，但并非全部都接入真实处理逻辑。PRD 后续验收应要求“参数可见”与“参数生效”分开验证。

### 4.5 任务中心 `/tasks`

**页面角色**：任务状态与进度中心。

**当前能力**：

- 按状态查看任务：全部、进行中、已完成、失败。
- 展示任务进度、当前步骤、错误和重试入口。
- 活跃任务通过轮询更新状态。
- 全局浮动任务按钮可进入任务中心。

**目标口径**：

任务中心最终不应只平铺底层原子任务，而应按业务层级聚合：

```text
批次任务
  └── 商品
        └── 输出图片 / 视频
              └── 工序步骤
                    └── 原子任务
```

迁移期可以先展示原子任务，但页面文案和分组应逐步向“批次/商品/结果”过渡。

### 4.6 结果管理 `/results`

**页面角色**：生成资产库。

**主要能力**：

- 展示已完成结果。
- 按场景分类筛选：主图、详情图、营销图、白底图、场景图、海报、其他。
- 搜索、网格/列表视图切换。
- 批量下载、删除、继续处理。

**数据口径**：

- `/tasks` 主要消费 `TaskQueue`。
- `/results` 主要消费 `ProcessedImage`。
- PRD 中的“结果完成”必须同时关注任务完成和结果记录可见，避免任务完成但结果库不可管理。

### 4.7 模板库 `/templates`

**页面角色**：模板资产和预设中心，也是当前最接近新版 Workbench Shell 的页面。

**主要区块**：

- 顶部工作台导航。
- 左侧分类栏。
- 中间模板网格。
- 右侧模板详情面板。

**模板类型**：

| 类型 | 内容 | 进入位置 |
|---|---|---|
| 场景预设 | 场景名称、用途、Prompt、比例、推荐模型 | `/workspace/scene?preset=` |
| 工具预设 | 工具类型、默认参数、输入要求 | `/tools` |
| 工作流预设 | 多步骤 pipeline、执行顺序、参数 | `/combo` |
| 品牌/参考资产 | Logo、参考图、品牌色、构图参考 | 后续进入模板资产管理 |

**当前边界**：

模板库已有静态 seed 和“使用模板进入工作流”的主链路。模板数据持久化、用户自定义模板、从结果保存为模板可后置。

### 4.8 设置中心 `/settings`

**页面角色**：运行配置与服务商凭据管理。

**主要配置**：

- 模型服务商凭据。
- 本地存储路径。
- 任务并发或运行偏好。
- 账户与安全相关设置。

**PRD 要求**：

设置页需要逐步从“填 key”升级为“配置健康检查”：告诉用户当前 provider 是否可用、缺什么、会影响哪些能力。

## 6. 能力模型

### 6.1 基础生成能力

基础生成能力负责从商品输入得到一批基础结果图。

| 能力 | 作用 | 输出 |
|---|---|---|
| 换背景 / 换场景 | 为商品生成指定背景或使用场景 | 单张或少量结果图 |
| 场景图生成 | 围绕商品卖点生成生活场景、营销图、主图等候选 | 多张候选图 |
| 套图生成 | 为每个商品生成 4/6/8 张不同用途的电商图 | 多张结果图 |

说明：套图生成是用户视角的生产入口，系统内部可以拆成多个场景生成任务。

### 6.2 后处理能力

后处理能力作用于已经生成或上传的图片。

| 能力 | 作用对象 | 推荐位置 |
|---|---|---|
| 扩图 | 原图、换背景结果、套图结果 | 自动流水线，可批量 |
| 高清化 | 原图、换背景结果、扩图结果 | 自动流水线，可批量 |
| 水印 | 任意最终图片 | 自动流水线，通常最后一步 |
| 局部编辑 | 任意单张结果图 | 结果详情页手动触发 |
| 图生视频 | 任意图片结果 | 可作为自动步骤，也可手动触发 |

### 6.3 推荐生成链路

```text
商品输入
  ↓
基础生成能力
  - 换背景 / 换场景
  - 场景图生成
  - 套图生成
  ↓
结果图池
  ↓
可选后处理流水线
  - 扩图
  - 高清化
  - 水印
  - 图生视频
  ↓
结果管理 / 下载 / 保存为模板
```

## 7. 生成矩阵预览

生成前必须展示矩阵预览，帮助用户确认成本、数量和产出结构。

示例 1：套图生成

```text
20 个商品
× 8 张套图模板
× 高清化
× 品牌水印
= 160 张最终图
```

示例 2：白底图批量

```text
50 个商品
× 每个商品 1 张白底图
× 扩图到 1:1
× 高清化
= 50 张最终图
```

矩阵视图建议：

| 商品 | 白底主图 | 生活场景 | 卖点图 | 细节图 | 对比图 | 步骤图 | 搭配图 | 海报图 |
|---|---|---|---|---|---|---|---|---|
| 商品 A | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 |
| 商品 B | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 | 生成 |

每个场景单元格支持查看或调整：

- 场景 Prompt。
- 图片比例。
- 模型策略。
- 是否扩图。
- 是否高清化。
- 是否加水印。
- 当前状态。

## 8. 任务与状态流

### 8.1 用户可见状态

| 状态 | 用户理解 | 底层映射 |
|---|---|---|
| 草稿 | 配置中，尚未提交 | 页面本地 draft |
| 排队中 | 已提交，等待处理 | `PENDING` |
| 生成中 | 基础生成或工具处理进行中 | `PROCESSING` |
| 后处理中 | 扩图、高清化、水印、视频等步骤进行中 | `PROCESSING` + step metadata |
| 部分失败 | 批次内部分结果失败 | 多任务聚合态 |
| 已完成 | 全部结果完成，可进入结果库 | `COMPLETED` + result record |
| 已失败 | 当前任务失败 | `FAILED` |
| 已取消 | 用户取消或系统取消 | `CANCELLED` |

### 8.2 底层状态机

```text
创建任务
  ↓
PENDING（排队中）
  ↓
PROCESSING（运行中）
  ↓
COMPLETED（完成）
  ↘
    FAILED（失败，可重试）
  ↘
    CANCELLED（取消）
```

### 8.3 重试与恢复规则

| 行为 | 产品语义 | 当前实现口径 |
|---|---|---|
| 自动重试 | 执行失败但未超过最大重试次数 | 原任务回到 `PENDING`，增加 retry count |
| 用户手动重试 | 用户希望重新跑失败/完成/取消任务 | 创建一条新任务，不原地复活旧任务 |
| 服务恢复 | 服务重启后处理卡住的运行中任务 | `PROCESSING` 任务按规则回到 `PENDING` 或变为 `FAILED` |

### 8.4 轮询原则

1. 页面内候选结果和任务进度优先走轻量 `/api/tasks/status`。
2. 状态接口只返回任务状态、进度、错误、步骤和结果摘要。
3. 不允许把大图、base64、完整 provider 响应重新放进轮询链路。
4. 结果资产通过结果表和文件/URL 引用消费，不通过任务状态接口承载大对象。

## 9. 模板资产中心

模板资产中心用于保存用户可复用的视觉资产和配置，不局限于 Prompt。

### 9.1 模板类型

| 模板类型 | 内容 | 用途 |
|---|---|---|
| 场景模板 | 场景名称、用途、Prompt、比例、推荐模型 | 套图生成、换场景 |
| 参考图模板 | 商品图、背景图、场景参考图 | 参考构图、背景、风格 |
| 后处理模板 | 扩图比例、高清化、水印、视频设置 | 批量生成后的自动处理 |
| 品牌模板 | Logo、水印位置、品牌色、固定文案 | 保持店铺视觉一致 |
| 结果模板 | 历史生成中效果好的结果图 | 下次作为风格或构图参考 |
| 工作流模板 | 多个处理步骤和参数组合 | 组合工作流和批量处理 |

### 9.2 模板中心结构

```text
模板资产中心
  - 场景模板
  - 工具预设
  - 工作流预设
  - 图片参考
  - 品牌资产
  - 我的收藏
```

### 9.3 保存为模板

每张生成结果图后续应提供“保存为模板”。

| 保存类型 | 说明 |
|---|---|
| 保存为参考图 | 下次作为风格、构图或背景参考 |
| 保存为场景模板 | 保存该图对应的 Prompt、比例和模型策略 |
| 保存为品牌模板 | 保存水印、Logo、版式配置 |
| 保存为工作流模板 | 保存从输入到后处理的一整套步骤 |
| 加入收藏 | 方便下次快速查找 |

## 10. 模型选择策略

普通用户不应直接面对复杂模型名称。默认展示模型策略，高级设置中再展开具体模型。

| 策略 | 用户理解 | 适用场景 |
|---|---|---|
| 推荐 | 系统自动选择 | 默认场景 |
| 质量优先 | 成本更高，结果更稳 | 主图、详情图、重要投放素材 |
| 速度优先 | 快速出预览 | 草稿、批量试风格 |
| 成本优先 | 控制大批量成本 | 大量 SKU 预览 |
| 商品保持优先 | 尽量保持商品主体不变 | 换背景、白底图 |
| 创意场景优先 | 更强氛围和构图 | 套图、海报、生活场景 |

## 11. 数据对象建议

以下为产品层数据对象，具体实现可映射到 Prisma、TaskQueue 和文件资产。

| 对象 | 说明 |
|---|---|
| `GenerationBatch` | 用户可见的批次任务，例如“春季新品 8 图套装” |
| `BatchProduct` | 批次中的一个商品 |
| `OutputItem` | 某商品下的一张结果图或视频 |
| `ProcessingStep` | 输出项中的工序步骤，例如生成、扩图、高清化、水印 |
| `AtomicTask` | 底层 `TaskQueue` 任务 |
| `TemplateAsset` | 模板资产中心中的统一模板对象 |
| `InputAssetRef` | 用户上传或选择的输入资产引用 |
| `ProcessedAsset` | 已完成、可展示、可下载、可复用的结果资产 |

建议关系：

```text
GenerationBatch 1 - N BatchProduct
BatchProduct 1 - N OutputItem
OutputItem 1 - N ProcessingStep
ProcessingStep 0 - 1 AtomicTask
InputAssetRef 可被 GenerationBatch / AtomicTask 引用
ProcessedAsset 可由 AtomicTask 生成
TemplateAsset 可被 GenerationBatch / OutputItem / ProcessingStep 引用
```

## 13. MVP 验收标准

### 13.1 产品验收

1. 用户能从首页或模板库进入场景生成流程。
2. 用户能上传商品图和参考图，并形成可提交的生成配置。
3. 用户能在提交前理解本次会生成多少张图、使用什么场景/比例/策略。
4. 用户提交后能在当前页面或任务中心看到清晰状态。
5. 任务完成后，用户能在结果管理中找到生成资产。
6. 用户能对结果进行下载、删除、继续处理或保存为模板。
7. 失败任务能给出用户可理解的失败原因和重试入口。

### 13.2 交互验收

1. 主导航在核心页面保持一致，用户能稳定返回首页、模板库、任务中心、结果管理和设置。
2. `/workspace/scene` 的三步流程不会让用户在配置、提交和查看结果之间迷路。
3. 模板库“使用模板”必须把用户带到正确工作流，并尽量带入模板参数。
4. 全局任务入口能让用户随时知道是否有任务在运行。
5. 任务状态变化不能依赖用户刷新页面。

### 13.3 工程验收

1. 新前端提交任务必须走 typed contract 或明确 adapter，不直接扩散任意 JSON 字符串。
2. 轮询必须走轻量状态接口，不携带大图/base64。
3. 新增任务类型时必须同步前端创建、worker 分发、任务中心展示、结果展示和类型映射。
4. `npm run build` 应通过。
5. Electron 桌面启动、SQLite、文件 URL、本地存储路径不能被破坏。

## 14. 关键风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| Worker 不是常驻后台进程 | 当前任务消费依赖 `/api/tasks/worker` 被触发 | 先在 PRD 中明确触发语义，后续考虑 Electron 主进程或独立 worker 常驻消费 |
| Worker 复杂度过高 | 调度、执行、provider、持久化、重试混在一个高风险模块 | Phase 5 拆分调度层、执行层、结果层和重试策略层 |
| 任务 JSON 过大 | 大 payload 会拖慢 SQLite 和轮询 | 输入和结果使用 asset reference，状态接口只保留轻量摘要 |
| 任务类型漂移 | 前端业务类型和 worker legacy 类型不一致 | 建立统一任务类型字典和 adapter 边界 |
| 结果双轨存储 | `TaskQueue.outputData` 与 `ProcessedImage` 容易口径不一致 | 明确 `/tasks` 看任务，`/results` 看资产，完成态必须验证资产可见 |
| 视频长任务阻塞 | 视频生成内部轮询时间长，可能占用并发槽位 | 视频任务独立标识和调度优先级，避免阻塞图片主链路 |
| Provider 配置不透明 | 用户填了 key 但不知道能力是否可用 | 设置页增加 provider 健康检查 |
| 旧新版并存 | 历史页面和文档可能误导后续实现 | Phase 6 清理旧前端，并把 PRD/GSD 文档更新为单一口径 |

## 15. 后续 GSD 推进顺序

当前 GSD 状态：Phase 1/2 已完成，Phase 3 进行中，Wave 4 待执行。

建议按以下顺序推进：
